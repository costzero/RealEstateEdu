## 1. 개요

### 1.1 제품 한 줄 정의
**부천·인천 지역 아파트·오피스텔 분양 정보**를 공공 API로 한곳에 모아 보여주고, 사용자의 청약 조건에 맞는 공고와 일정을 알려주는 모바일 앱(Android/iOS)과 반응형 웹. (사용자 웹은 푸시 알림을 제외하고 앱과 동일한 기능을 제공한다)

### 1.2 배경
- 분양 정보가 청약홈, LH, 시행사 홈페이지 등에 흩어져 있어 지역 단위로 모아 보기 어렵다.
- 청약 일정(접수일, 당첨자 발표일 등)을 놓치기 쉽다.
- 분양가가 적정한지 판단하려면 주변 시세와 과거 경쟁률을 따로 찾아봐야 한다.

### 1.3 목표
- 부천·인천 지역 분양 정보를 **하루 1회 자동으로 갱신**해서 제공한다.
- 관심 단지와 청약 일정을 **푸시 알림과 이메일**로 알려준다.
- 분양가, 주변 시세, 경쟁률, 내 가점을 **한 화면에서 비교·판단**할 수 있게 한다.

### 1.4 범위

| 구분 | 1차 범위 | 1차 제외 |
|---|---|---|
| 분양 유형 | 아파트, 오피스텔(도시형생활주택·민간임대 등 청약홈 제공 유형 포함), 공공분양 | 상가 |
| 플랫폼 | 반응형 웹, Android 앱, iOS 앱 | - |
| 회원 | 자체 회원가입(이메일/비밀번호/전화번호 + SMS 인증), 네이버·카카오·구글·Apple(iOS만) 로그인 | - |

### 1.5 타겟 사용자
- 부천·인천 및 인근에서 내 집 마련을 준비하는 무주택자
- 신혼부부, 생애최초 등 특별공급 대상자
- 분양권·입주권 시세에 관심 있는 실수요자

### 1.6 서비스 지역
- 1차: **부천시 전역** (원미구·소사구·오정구, 대장지구 등 신규 택지 포함) + **인천 전역**
- 확장: 1차 이후 **경기 지역**으로 확장할 예정이다.

## 2. 시스템 구성 개요

```
 [공공데이터 API] ──(하루 1회 수집)──▶ [자체 웹서버: APM]
                                          ├─ 데이터 저장 (MariaDB)
                                          ├─ 앱·웹용 REST API 제공 (PHP)
                                          ├─ 회원 인증 (PHP)
                                          ├─ 관리자 웹페이지 (팝업 관리 포함)
                                          ├─ 이메일 발송 (네이버 SMTP) / SMS 발송 (대행사 미정)
                                          └─ 푸시 발송 요청 ──▶ [Firebase FCM] ──▶ 사용자 기기(앱)
                                                ▲
 [Flutter 앱 (Android / iOS)] ───HTTPS────────┤
 [사용자 웹 (반응형)] ───────────HTTPS────────┘
```

| 구성 요소 | 역할 | 방침 |
|---|---|---|
| **웹서버 (APM)** | 데이터 수집·저장, 앱·웹 API, 회원 인증, 관리자 페이지 | 보유한 리눅스 서버에 Apache + PHP + MariaDB로 구성. 백엔드는 순수 PHP(프레임워크 미사용) |
| **데이터베이스** | 분양정보, 회원, 관심 정보, 팝업, 알림 이력 저장 | MariaDB |
| **Flutter 앱** | 사용자 화면, 소셜 로그인 SDK 연동, 푸시 수신 | 하나의 코드로 Android / iOS 동시 출시 |
| **사용자 웹** | 사용자 화면 (앱과 동일 기능, 푸시 제외) | 반응형(PC·태블릿·모바일). React를 부분적으로 사용 (Vite 빌드 후 번들 배포) |
| **Firebase** | **FCM(푸시 알림)만 사용** | 인증, DB 등 다른 Firebase 기능은 쓰지 않음 |
| **이메일 발송** | 알림 메일, 아이디·비밀번호 찾기 메일 | 네이버 SMTP. 가입자가 많아지면 외부 발송 서비스 검토 |
| **SMS 발송** | 가입 시 전화번호 인증, 아이디·비밀번호 찾기 | 문자 발송 대행사 미정 |
| **외부 API** | 공공데이터, 지도, 소셜 로그인 | 서비스키는 서버에만 보관하고 앱에 넣지 않음 |

## 3. 데이터 소스

모두 공공데이터 기반이다. 사용 전에 각 API의 **이용허락범위**(상업적 이용 가능 여부)를 확인하고 기록해 둔다.

| 구분 | 데이터 | 출처 | 용도 |
|---|---|---|---|
| 분양 | 청약홈 분양정보 (APT, 오피스텔·도시형·민간임대, 무순위·잔여세대, 주택형별 상세) | 한국부동산원 (data.go.kr) | 분양 목록·상세·일정 |
| 분양 | 청약 경쟁률·당첨가점 | 한국부동산원 | 경쟁률, 가점 비교 |
| 분양 | LH 분양·임대 공고 | 한국토지주택공사 | 공공분양 공고 |
| 분양 | GH 공고 | 경기주택도시공사 | 공공분양 공고 (API 제공 여부 확인 필요) |
| 시세 | 아파트 매매·전월세 실거래가 | 국토교통부 | 주변 시세 비교 |
| 시세 | 분양권·입주권 실거래가 | 국토교통부 | 분양권 시세 |
| 시세 | 부동산 통계 (가격지수, 미분양) | 한국부동산원 R-ONE | 지역 동향 |
| 단지 | 공동주택 단지 정보, 건축물대장 | 국토교통부 | 단지 기본정보 |
| 입지 | 학교 정보 | NEIS 교육정보 개방포털 | 주변 학교 |
| 입지 | 대중교통 정보 | TAGO | 주변 교통 |
| 지도 | 지도 표시, 주소→좌표, 주변시설 검색 | **카카오맵 / 카카오 로컬** | 지도·주변시설 |

- 청약홈 API에서 실제 사용할 오퍼레이션, 응답 항목, 호출 한도는 API 키를 발급받은 뒤 확인해서 이 문서에 반영한다.

### 3.1 수집 방식
- 사용자 요청마다 공공 API를 직접 부르지 않는다. 서버 배치(cron)가 정기적으로 데이터를 받아 MariaDB에 저장하고, 웹과 앱은 자체 DB를 조회한다.
- 이렇게 하면 API 호출 한도와 응답 지연의 영향을 줄이고, 관심 조건 매칭과 알림 발송에 같은 데이터를 쓸 수 있다.

### 3.2 주요 항목 (예상)
API 응답을 확인한 뒤 확정한다.

- 단지명, 분양 유형(아파트/오피스텔 등), 공급 위치(시도·시군구·주소)
- 공급 규모(세대수), 주택형·전용면적, 분양가
- 모집공고일, 청약 접수 일정(특별공급·1순위·2순위 등), 당첨자 발표일, 계약 일정
- 시행사·시공사, 문의처, 청약홈 공고 링크

### 3.3 데이터 이용 원칙
- 앱과 웹 안에 **출처를 표시**한다. (예: "자료 출처: 한국부동산원 청약홈, 국토교통부")
- 공식 서비스로 오인되지 않게 "청약홈" 등 기관 명칭이나 로고를 브랜딩에 쓰지 않는다.
- 상세 화면에 **면책 문구와 모집공고문 원문 링크**를 둔다. (정확한 일정과 자격은 원문으로 확인하도록 안내)
- 모집공고문 PDF는 재배포하지 않고 원문 링크로 연결한다.

## 5. 회원

### 5.1 가입 방식

| 구분 | 방식 | 처리 방침 |
|---|---|---|
| **일반 회원가입** | 이메일(아이디) + 비밀번호 + **전화번호(SMS 인증)** | PHP 서버에서 가입·로그인 처리. 이메일과 전화번호는 필수. 비밀번호는 단방향 해시(PHP `password_hash`)로 저장 |
| **간편가입** | 네이버, 카카오, 구글, **Apple** | 앱에서 각 회사 SDK로 로그인 → 받은 토큰을 서버로 전달 → **서버가 해당 회사에 토큰을 직접 검증** → 회원 조회 또는 신규 가입. 처음 가입할 때도 **이메일과 전화번호(SMS 인증)를 반드시 받는다** |

- Apple 로그인은 iOS App Store 정책 대응을 위해 포함하며, **iOS에서만 노출**한다.
- 알림 메일과 아이디·비밀번호 찾기 메일은 **네이버 SMTP**로 발송한다.
- 인증 문자는 문자 발송 대행사를 통해 보낸다. (대행사 미정)

**공통 방침**
- 로그인에 성공하면 **웹은 세션**, **앱은 서버가 발급한 자체 로그인 토큰**을 사용한다. (토큰 종류와 만료 기간은 미정)
- 자동 로그인을 지원한다.
- 간편가입 회원은 이메일이 아니라 **"제공자 + 제공자의 고유 ID"** 로 식별한다.
- 이메일이 같다는 이유로 계정을 자동으로 합치지 않는다. 계정 연결은 로그인한 상태에서 사용자가 직접 한다.

### 5.2 가입 절차

```
[가입 방식 선택: 일반 / 네이버 / 카카오 / 구글 / Apple(iOS만)]
        │
        ▼
[1단계: 약관 동의]  ── 필수: 서비스 이용약관, 개인정보 수집·이용, 만 14세 이상 확인
        │             선택: 알림 수신, 마케팅 정보 수신, 맞춤 정보(청약 자격) 수집·이용
        ▼
[2단계: 기본 정보]  ── 일반가입: 이메일, 비밀번호, 전화번호, 닉네임
        │             간편가입: 제공자에게서 받은 정보로 자동 입력, 이메일·전화번호·닉네임 확인
        ▼
[2-1단계: 전화번호 SMS 인증 (일반가입·간편가입 공통)]
        │             입력한 전화번호로 인증번호 문자 발송 → 인증번호 입력 → 일치하면 가입 확정
        │             (재발송 가능, 유효 시간과 재시도 횟수는 제한)
        ▼
[3단계: 맞춤 정보 (선택, 건너뛰기 가능)]
        │             관심 조건 / 청약 자격 / 특별공급 해당 여부
        ▼
[4단계: 알림 설정]  ── 푸시(앱)·이메일 알림 허용, 알림 종류 선택
        │
        ▼
     가입 완료 → 홈
```

- 3단계 맞춤 정보는 **가입할 때 건너뛸 수 있고**, 나중에 "내 정보"에서 입력·수정할 수 있다. 가입 이탈을 줄이기 위해서다.

### 5.3 가입 항목

#### (1) 기본 정보
| 항목 | 일반가입 | 간편가입 | 비고 |
|---|---|---|---|
| 이메일 | 필수 | 필수 (제공자가 주면 자동 입력) | 카카오는 선택 동의, 애플은 숨김 이메일일 수 있음 |
| 비밀번호 | 필수 | 없음 | |
| 전화번호 | 필수 (SMS 인증) | 필수 (SMS 인증) | |
| 닉네임 | 필수 | 자동 입력 후 수정 가능 | |

#### (2) 관심 조건 (선택) – 맞춤 추천·알림에 사용
| 항목 | 예시 |
|---|---|
| 관심 지역 | 부천(원미구 / 소사구 / 오정구), 인천(구·군 단위), 부천·인천 전체 |
| 관심 주택 유형 | 아파트, 오피스텔, 도시형생활주택, 공공분양 |
| 희망 평형(전용면적) | 59㎡ 이하, 60~84㎡, 85㎡ 초과 |
| 예산(가격대) | 구간 선택 |

#### (3) 청약 자격 정보 (선택) – 가점 계산·자격 안내에 사용
| 항목 | 용도 |
|---|---|
| 무주택 여부 / 무주택 기간 | 가점 계산, 자격 판단 |
| 세대주 여부 | 1순위 자격 판단 |

| 과거 당첨 이력 (재당첨 제한 여부) | 자격 판단 |

#### (4) 특별공급 해당 여부 (선택)
| 항목 |
|---|
| 신혼부부 (혼인 기간) |
| 생애최초 |

> 청약 자격 정보는 민감도가 높으므로 **선택 수집**으로 하고, 별도 동의를 받으며, 언제든 삭제할 수 있게 한다.
> 이 정보로 계산한 결과는 **참고용**이며 실제 자격은 모집공고문과 청약홈에서 확인하도록 안내한다.

## 8. 처리 프로세스

### 8.1 데이터 수집 (웹서버, 하루 1회)
```
[매일 새벽 정해진 시각에 자동 실행]
  1. 공공데이터 API 호출 (분양정보 → 경쟁률 → 실거래가 순)
  2. 부천·인천 지역 데이터만 골라냄
  3. 기존 데이터와 비교해서 신규·변경 사항을 반영
  4. 신규 단지는 주소를 좌표로 변환해서 저장
  5. 수집 결과(성공/실패, 건수)를 로그로 남김
  6. 신규 공고나 일정 변경이 있으면 → 알림 대상자를 골라 푸시·이메일 발송
```
- API 장애로 실패하면 **기존 데이터를 유지**하고 재시도한다. 계속 실패하면 관리자에게 알린다.
- 관리자가 수동으로 다시 수집할 수 있다.

### 8.2 알림 (푸시·이메일)
```
[알림 사건 발생: 신규 공고 / 접수일 임박 / 발표일 / 공지]
  → 서버가 알림 대상 회원과 기기 추림 (알림 채널·종류 설정, 수신 동의 확인)
  → 푸시: FCM으로 발송 요청 / 이메일: 네이버 SMTP로 발송
  → 사용자 기기에 알림 표시 → 누르면 해당 화면으로 이동
```
- 앱을 설치하거나 로그인할 때 기기의 푸시 토큰을 서버에 등록하고, 바뀌면 갱신한다.

### 8.3 인증
```
[일반 가입] 앱·웹: 정보 입력 → 서버: 인증번호 문자 발송 (SMS 대행사) → 앱·웹: 인증번호 입력 → 서버: 확인 후 가입 확정
[일반 로그인] 앱·웹: 이메일·비밀번호 입력 → 서버: 확인 (전화번호 인증 완료 회원만) → 웹은 세션, 앱은 로그인 토큰 발급
[간편] 앱: SDK 로그인 → 토큰 전달 → 서버: 제공자에게 검증 → 회원 조회 / 신규면 이메일·전화번호(SMS 인증) 받아 가입 → 로그인 토큰 발급
[공통] 앱: 토큰 안전하게 저장 → 이후 요청에 사용 → 만료되면 자동 갱신
```

## 12. 정책·법적 고려사항

- **공공데이터 이용허락범위**: API마다 확인하고 기록한다.
- **개인정보 처리방침**: 수집 항목(이메일, 전화번호, 선택 시 청약 자격 정보), 목적, 보관 기간, 파기 절차를 명시한다. 특히 청약 자격 정보는 선택 동의를 따로 받는다.
- **정보통신망법**: 광고성 푸시는 별도 수신 동의가 필요하고, 야간 발송은 추가 동의가 필요하다. 수신 동의 사실은 정기적으로 다시 안내한다.
- **표시광고법**: 분양 광고는 "광고"로 표시하고 과장 광고를 하지 않는다.
- **공인중개사법**: 매물 중개나 수수료 모델은 넣지 않는다. 정보 제공 서비스로 한정한다.
- **앱스토어 정책**: 앱 안에서 회원 탈퇴 제공 (iOS 필수), 소셜 로그인 관련 요건 확인.
- **면책**: 데이터는 참고용이며 실제 청약은 모집공고문과 청약홈 기준이라고 안내한다.

> 출시 전에 약관과 개인정보 처리방침은 전문가 검토를 받는 것을 권장한다.
